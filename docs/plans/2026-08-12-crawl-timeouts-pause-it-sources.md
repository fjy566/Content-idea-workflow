# 采集超时、暂停恢复与中国 IT 数据源设计

## 目标

解决单个数据源长时间阻塞导致一轮采集超过预期的问题，并让用户可以看到进度、请求暂停、稍后继续未完成的来源。同时扩展一批已验证可以返回 RSS/Atom 的中国 IT 公开源。

## 产品约定

- 单源超时默认 30 秒，可按源调整为 5–300 秒。
- 一轮总超时默认 300 秒，手动采集时可调整为 30–3600 秒。
- 超时只阻止启动后续来源；已经完成的来源、已写入的热点和日志不回滚。
- 暂停是协作式暂停：当前来源结束（成功或失败）后才停，不强制中断正在进行的 HTTP/Playwright 请求。
- 继续采集会复用原轮次，只处理尚未完成的来源，避免重复拉取已完成来源。
- 启动时只在真正全新数据库补充默认中国源；已有数据库不清理、不禁用、不改写用户来源。新增精选源通过“补充中国精选源”显式操作。

## 实现方案

### 状态与持久化

`CrawlRun` 保存选中的来源 ID、已完成来源 ID、总超时和暂停请求。轮次状态使用 `pending → running → success/partial/timeout/paused`。`Source.timeout_seconds` 保存单源超时，旧数据库由兼容迁移补列并使用 30 秒默认值。

### 调度边界

轮次启动时计算单调时钟截止时间；每次启动新来源前检查暂停和总超时，并将剩余时间传给采集器。采集器的 HTTPX 和 Playwright 请求均使用这个更小的剩余时间，因此一个慢源不会无限占用整个轮次。来源完成后立即持久化进度和日志。

### 中国 IT 源

精选目录新增 InfoQ 中国、开源中国、V2EX、SegmentFault、雷锋网、人人都是产品经理。它们的 RSS/Atom 地址在实现前逐一做了 HTTP 200 和 feedparser 可解析性检查；不稳定或返回 HTML 的地址不加入默认目录。

## 验证重点

- 单源字段和全局默认值都能正确传给 HTTPX/Playwright。
- 总超时后不再启动下一来源，并记录 timeout 日志。
- 暂停请求在当前来源完成后进入 paused；继续后只处理剩余来源。
- 手动采集只使用用户勾选的启用来源，轮次参数在后台任务中仍然有效。
- 既有自定义来源保持不变；精选源补充只新增缺失 URL。
- 页面按钮、进度、来源选择和日志清空操作均有路由回归测试。
