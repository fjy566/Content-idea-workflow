# ADR 0004：用持久化轮次状态实现有界采集控制

- 状态：已采用
- 日期：2026-08-12

## 背景

RSS、静态页面和动态页面的响应速度差异很大。只设置 HTTP 客户端默认超时无法表达“这一轮最多运行多久”，也无法在浏览器刷新后恢复暂停进度。

## 决策

把控制信息写入 SQLite：来源保存单源超时，采集轮次保存总超时、选中来源和已完成来源。调度器在每个来源边界检查暂停/超时，并把剩余秒数传给 HTTPX 或 Playwright。暂停不强杀当前请求；请求结束后保存进度并进入 `paused`，恢复时继续同一个轮次。

## 后果

- 正面：页面刷新、进程短暂重启后仍能看到轮次进度；超时和暂停都可解释、可审计；已完成来源不会因恢复而重复采集。
- 正面：SQLite 单机架构不需要引入队列服务，适合个人使用。
- 限制：暂停不是硬中断，最坏需要等待当前来源的单源超时；单轮内仍是顺序采集。
- 限制：如果进程在一个来源请求中被强制关闭，无法在请求中途保存该来源的完成状态；重新继续时会重试该来源。
