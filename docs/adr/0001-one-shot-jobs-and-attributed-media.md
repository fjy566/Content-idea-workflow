# ADR 0001：单轮采集任务与可追溯配图

- 状态：接受
- 日期：2026-08-11

## 背景

平台为个人单机使用，但采集、AI 分析和图片处理的耗时与费用不同。原有采集没有持久化进度，并在结束后自动调用大模型；图片只能手工调用生成 API，也没有搜索图片的版权来源记录。

## 决策

1. 将每次采集建模为 `CrawlRun`，每个数据源产生 `CrawlLog`，后台调度和手动采集共用同一套单轮执行器。
2. 采集和 AI 分析彻底解耦；只有显式用户操作才能调用聊天或图片 API。
3. 中国读者工作流的关键词搜图固定使用 360 图片中国搜索；下载到本地并保存原始页面 URL。搜索失败直接提示用户，不静默切换外国图片源；图片生成仍走用户配置的图片 API。
4. 推荐训练由用户选择自动、CPU 或 CUDA。CUDA 只有在 NVIDIA GPU 和 XGBoost CUDA 支持均可用时开放；自动模式在 CUDA 不可用时使用 sklearn CPU。模型工件记录请求设备、实际设备、算法、特征数和验证误差。
5. 训练作为持久化的 `RecommenderTrainingRun` 后台任务运行，状态接口提供阶段、进度、样本、指标和错误信息；保持服务端渲染，只用原生 JavaScript 轮询，不引入前端框架。

## 结果

- 用户能分辨免费本地操作与消耗 Token 的操作，并掌控每次调用。
- 采集失败可以定位到具体轮次和数据源。
- 中国搜索图片具有可追溯的来源信息，但仍需用户在发布前确认具体许可要求；历史文章中的旧素材不因迁移被破坏。
- GPU 是可选加速，不成为平台运行的硬依赖。
- 用户可以在 CPU 与 CUDA 之间做出明确选择；刷新页面不会丢失训练进度或最终指标。

## 备选方案

- 浏览器搜索引擎抓图：来源和许可不稳定，拒绝。
- Celery/Redis 任务队列：对个人单机部署过重，暂不采用；使用 FastAPI 后台任务和 SQLite 状态表。
- 只支持 CUDA：会降低可移植性，拒绝。
