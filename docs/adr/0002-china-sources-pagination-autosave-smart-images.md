# ADR 0002：中国数据源、SQL 分页、编辑器自动保存与智能配图

- 状态：接受
- 日期：2026-08-11

## 背景

平台已经能采集真实热点和生成文章，但热点列表曾经先加载最多 1000 条再在 Python 中分类，数据源中还混有外国 RSS；编辑器的按钮点击会让浏览器焦点离开 textarea，图片无法稳定插入用户最后的光标位置；文章配图也只能均匀插入，且长时间编辑只有本地临时草稿。

## 决策

1. 在 `Topic` 上落库 `category` 并建立索引，仪表盘使用 `COUNT/OFFSET/LIMIT` 直接分页；无来源的历史话题保留但不进入热点雷达。
2. 精选 RSS 使用小型、可审查的中国来源目录管理，并仅在真正的全新数据库中自动初始化。来源地域只决定默认值，不构成用户自定义来源白名单；启动和升级不得删除、停用或改写已有 `Source` 及其 `RawItem`。
3. 编辑器同时使用本地草稿和服务端自动保存。服务端保存为 JSON 接口，不改变页面；保存请求携带快照，只有快照仍是当前版本时才清除脏状态，避免覆盖用户刚输入的新内容。
4. 图片生成阶段先根据标题和小标题生成多张相关图片，再由用户选择智能章节插入、均匀插入或仅保存素材。智能插入只让文本模型返回图片编号、标题和原文短语，实际 Markdown 插入、索引校验、重复防护和回退均在本地完成。
5. 关键词搜图只使用中国图片搜索源；失败不再回退外国引擎，避免与“中国读者/中国数据源”产品边界冲突。

## 结果

- 热点库展示稳定，分页不会随 Python 分类结果漂移，单机数据量扩大后查询成本更可控。
- 数据源页面可以明确看见中国精选源；现有来源和用户后续添加的公网来源都由用户自行管理，不受启动迁移影响。
- 长文编辑期间服务端自动保存，网络或服务异常时仍有本地副本；编辑器工具栏和素材按钮不会吞掉最后一次正文光标。
- 智能排版有严格 JSON 约束和无模型回退，模型格式错误不会让文章整体生成失败。

## 备选方案

- 浏览器端富文本编辑器：会引入复杂的 HTML/Markdown 双向转换和图片上传状态，当前单机产品优先保留可读、可导出的 Markdown。
- 每次请求加载全部热点：实现简单但分页无意义，放弃。
- 中国搜索失败时自动用外国开放图片库：可能提高成功率，但违反数据源边界，放弃。
- Redis/Celery 任务队列：个人单机部署过重，当前使用 FastAPI BackgroundTasks 与 SQLite 持久化轮次状态。
